# 2. Systematic Redundancy Allocation

The protocol operates in a **Systematic FEC Mode** with an adaptive redundancy rate bounded between $5\%$ and $30\%$:

1.  **Source Transmission:** The first $K$ packets contain the original source symbols unchanged, allowing high-performance, zero-overhead decoding under clean network conditions.
2.  **Adaptive Parity Generation:** Parity is computed **per block, per downstream link**, by the *sender*, using the loss rate $\rho$ that each child reports for its own link over a 2-second sliding window. A block fails on a link when more than $E$ of its $K + E$ symbols are lost. The parity symbol count $E$ is the smallest count that keeps that probability at or below the per-hop block-failure target $p_{\text{fail}} = 10^{-3}$, between a floor of one symbol and a $30\%$ ceiling:
    $$E = \min\left\{ e \in [1,\ \lceil 0.30K \rceil] \;:\; \Pr\left[\text{Bin}(K + e,\ \rho) > e\right] \le p_{\text{fail}} \right\}, \qquad E = \lceil 0.30K \rceil \text{ if no such } e \text{ exists}$$

    With $K = 16$: $E = 1$ below $\rho \approx 0.3\%$, $E = 2$ up to $1\%$, $E = 3$ at $2\%$, $E = 4$ at $3\%$, and the ceiling $E = 5$ from $5\%$. Above $5\%$ loss the ceiling cannot hold the target (at $\rho = 10\%$, $1.4\%$ of blocks per hop fail; at $15\%$, $8.3\%$), and the remainder falls to the PULL path. An earlier rule, $E = \lceil \text{clamp}(2\rho K, 0.05K, 0.30K) \rceil$, sized parity to the mean loss. At $K = 16$ the binomial spread around that mean left $4.5\%$ of blocks per hop to PULL at $\rho = 2\%$, which exceeds the PULL reserve a few hops down.

    **Measuring $\rho$.** The child counts, for each block its parent pushed, the source symbols ($\text{ESI} < K$) that had not arrived when the block decoded, over $K$. The parent sends the source symbols first, so this ratio is the link loss whatever parity was sent. A source symbol that arrives after its block decoded was late, not lost, and is taken back out of the count. A block whose `BLOCK_PROOF` arrived but which the PULL path completed counts with its missing source symbols. A block with no `BLOCK_PROOF` does not count: the child attached in the middle of the push.
3.  **Proactive Dispersion:** Parity symbols are distributed across the Multi-Forest active parent sets. A downstream child reconstructs the original payload locally from the parity symbols in all but $p_{\text{fail}}$ of the blocks per hop while $\rho \le 5\%$. The residue compounds with depth, $1 - (1 - p_{\text{fail}})^{d}$, about $0.7\%$ of blocks at depth $7$, and is served from the PULL reserve (Ch1 §1.2.1 §1.3).
4.  **Rate Update Interval:** $E$ is recalculated once per segment (every $1.0\text{ s}$) and communicated to the encoder via a local control signal. No wire format change is required; the ESI field already distinguishes source ($\text{ESI} < K$) from parity ($\text{ESI} \ge K$) symbols. The child's loss rate $\rho$ reaches the parent in the per-segment `PROOF_OF_UPLOAD` receipt (Ch5 §5.2.3, `LossRate`), which every child already sends once per segment per tree.
5.  **Parity is paid for in slots.** The mean parity $\bar{E}_v$ a relay currently sends enters its overhead factor $\Omega_v = (1 + \bar{E}_v/K)(1 + f_{\text{frame}})$ and therefore its slot count $K_v(m)$ (Ch1 §1.2.1). Rising loss raises parity, which *lowers* the slot count and releases a child through the drain path — so the adaptive-parity loop is damped rather than self-reinforcing. A relay that treated parity as free would oversubscribe its uplink by $6$–$30\%$, induce the very loss it then repairs, and spiral.
