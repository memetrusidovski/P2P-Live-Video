# 2. IP Subnet Penalties

A massive cluster of Sybil nodes run by a single attacker will often originate from the same cloud hosting provider or botnet block.

**IP Subnet Clustering Auditing:** 
The auditing node maps the addresses of the signers in the receipt bundle **that it can resolve**. If more than $20\%$ of the resolved signers fall in the same $/24$ IPv4 subnet or $/48$ IPv6 prefix, the bundle's score is penalized by:
$$\text{PenaltyFactor} = 1 - \frac{\text{ClusteredIPs}}{\text{ResolvedIPs}}$$

## What the Auditor Can Resolve, and What It Cannot

A receipt carries the downloader's NodeID and no address — by design, since no peer declares its own address (Ch2 §2.2.3), and a downloader-declared address would in any case be worthless here: the downloader is the party suspected of colluding. The only trustworthy address for a signer is one **observed by a third party**. A verifier of a `RANK_PROOF` (Ch5 §5.2.2) holds sixteen sampled receipts and resolves their signers from three sources, in order of cost:

| Source | Covers | Cost |
| :--- | :--- | :--- |
| The verifier's own sessions, Passive Set and k-buckets | signers it has itself observed — rare for a stranger's downloaders | none |
| `FIND_NODE(Downloader NodeID)` (Ch2 §2.1) | **relay-class** signers: every reachable relay is a DHT server and is held, with its guardian-observed address, by the nodes closest to its ID | one DHT walk, $1$–$3$ s, performed **lazily after admission**; a bundle found clustered revokes the admission (`DRAIN_NOTICE`, reason `PREEMPTED`) |
| nothing | **leaf-class** signers: `LEAF`, `LEAF_PRIVATE` and every `SYMMETRIC` node run the DHT in client mode and are in nobody's buckets (Ch2 §2.3.2) | — |

The sampled receipts carry each signer's `NodeClass` (the child advertisement, §5.2.1), so the verifier knows in advance which signers it can resolve. **Receipts from leaf-class signers cannot be diversity-checked by anyone but the uploader that served them**, and the uploader is the party whose rank is in question.

An earlier draft said the penalty "mathematically nullifies the value of thousands of fake PoU receipts generated by a single server farm." It does so only for signers with a resolvable address. The honest statement is this: **a colluding uploader with leaf-class Sybil downloaders can inflate its rank at the cost of one identity per distinct receipt key** — $\approx 10$ ms of hashing per identity (Ch2 §2.2.1), and no bytes need to be sent, since the Sybils sign whatever the uploader asks. The receipt-cap and distinctness checks of §5.2.2 bound *how much* each fabricated receipt is worth and force the Sybils to be distinct identities; they do not make the identities expensive. Nothing in this protocol does.

What bounds the **damage** of forged rank is therefore not the rank proof but the places rank is spent, each of which has its own bound that does not depend on the rank being honest:

*   **Enhancement-tree slots** (Ch1 §1.2.2): a forged rank lets the attacker's identities preempt lower-ranked children, but an *honest* parent caps children from one prefix at $c_p(K_v(m))$ per tree (Ch2 §2.2.2), so an attacker with one prefix takes at most that many slots per honest parent per tree, whatever rank it shows. The theft is one slot per prefix per parent per tree, taken from a rank-0 child that any genuine contributor would also have preempted.
*   **Multi-tree standing** (Ch1 §1.2.1): forged rank buys interior status in every tree. The gate raises the cost of that from nothing to $S$ Sybil identities per minute; it does not bound the blast radius, which is bounded by the attacker's children observing non-delivery within one segment, scoring it down on reliability, and leaving (per-tree repair, Ch3 §3.3), and by the prefix cap on how many of the forest's children it can hold at all.
*   **Accuser standing** (§5.3.3): forged rank makes a Sybil a countable accuser, but an accusation counts only with re-verified evidence signed by the suspect; standing without evidence evicts nobody.

Chapter 8 owes a measurement of how much enhancement-layer quality a single-prefix attacker can take with forged rank at $N = 10^6$; the expectation from the bounds above is one slot per honest parent per tree, which is what a genuine contributor with one prefix would also hold.

**Small-Swarm Guard:** Like the symmetric-edge detector, the subnet penalty is suppressed when $N_{\text{guard}} = \max(N_{\text{record}}, |\text{peers observed locally}|)$ is below $N_{\text{collusion}} = 20$ — the same forgery-resistant swarm-size input, for the same reason (see [1. Graph Collusion Auditing](1_graph_collusion_auditing.md)). In a small stream it is common and legitimate for several viewers to share a $/24$ — friends watching from the same ISP, or a household behind one CGNAT block — and at that scale the receipts being discounted are too few to be worth attacking anyway.
